# UntitledGameEngine

Высокопроизводительный (для консоли) 2D движок на архитектуре **ECS** (Entity Component System). Движок использует двойную буферизацию для устранения мерцания, пространственное хеширование для быстрой физики и систему фазовых событий.

---

## 🏗 Архитектура

Движок разделяет данные и логику на три уровня:
1.  **Entities (Сущности):** Легковесные объекты (ID + набор компонентов).
2.  **Components (Компоненты):** Чистые данные (позиция, скорость, символы).
3.  **Systems (Системы):** Изолированная логика, обрабатывающая компоненты.

---

## 🚀 Быстрый старт

### Инициализация игры
Класс `Game` является входной точкой и управляет жизненным циклом (Main Loop).

```python
from game import Game
import numpy as np

game = Game(
    resolution=(100, 35), # Ширина и высота консоли
    fps=30,               # Кадры в секунду
    tickspeed=60,         # Частота обновления физики (Fixed Update)
    background_sym='.'    # Фоновый символ
)
```

### Создание сущности
Движок использует **Fluent API** для сборки объектов:

```python
from entity import Entity
from components import Transform, Render, Physics, Collider

player = Entity(id=1).add_components(
    Transform(pos=np.array([10.0, 5.0])),
    Render(default_sym='@', draw_priority=10),
    Physics(mass=1.0, velocity=np.zeros(2), acceleration=np.zeros(2)),
    Collider(half_x=0.5, half_y=0.5, elasticity=0.2)
)
```

---

## 📦 Компоненты (API данных)

Все основные данные хранятся в `components.py`:

* **Transform:** Хранит `pos` (вектор `numpy`). Имеет флаг `dirty`, который системы используют для оптимизации расчетов.
* **Physics:** Содержит `velocity`, `acceleration` и `mass`. Флаг `is_static` исключает объект из физического движка (для стен/пола).
* **Collider:** Описывает AABB (Axis-Aligned Bounding Box). Поля `half_x` и `half_y` — это половина ширины и высоты.
* **Render:** Управляет визуалом через `default_sym`. Поле `draw_priority` определяет порядок отрисовки (слои).
* **Script:** Позволяет вешать функции `on_tick` (физика) и `on_frame` (рендер) прямо на сущность.

## ⚙️ Системы и API движка

### 🕹 Ввод (Input System)
Движок слушает клавиатуру в реальном времени.
* `game.input.is_pressed('w')` — проверка зажатия клавиши.
* `game.input.bind_key('space', on_press=callback)` — подписка на событие нажатия.

### 🎥 Рендеринг (RenderSystem)
* **Double Buffering:** Движок формирует кадр в `back_buffer` и выводит его целиком, что убирает мерцание консоли.
* **Camera API:** Вы можете создать сущность с компонентом `Camera`. Движок будет отрисовывать мир относительно неё, поддерживая `zoom` и `offset`.
* **Оптимизация:** Рендерятся только те объекты, которые находятся внутри "фрастума" (области видимости) активной камеры.

### 🌍 Физика и Коллизии
* **Fixed Timestep:** Физика в `PhysicsSystem` считается с фиксированным шагом (аккумулятор времени в `game.py`), что делает поведение тел предсказуемым.
* **Spatial Hashing:** В `CollisionGrid` мир разбит на сетку. Проверка столкновений идет только между объектами в соседних ячейках сетки, что позволяет обрабатывать сотни объектов.
* **Y-Scale:** Движок автоматически корректирует вертикальную скорость (`y_scale_vec`), чтобы компенсировать разницу в высоте и ширине символов консоли.

### 📅 Система событий (EventBus)
События обрабатываются по фазам в `event_system.py`:
1.  `INPUT` (0) — Чтение команд пользователя.
2.  `SIMULATION` (1) — Расчет перемещений.
3.  `REACTION` (2) — Обработка столкновений и триггеров.
4.  `RENDER` (3) — Финализация визуального состояния.

## 📜 Пример скриптинга

Логика движения игрока без создания новых классов:

```python
def player_controller(entity, game):
    physics = entity.physics
    if game.input.is_pressed('a'):
        physics.velocity[0] -= 0.5
    if game.input.is_pressed('d'):
        physics.velocity[0] += 0.5

# Регистрация в ECS
player.add_component(Script().add_tick(player_controller))
```
